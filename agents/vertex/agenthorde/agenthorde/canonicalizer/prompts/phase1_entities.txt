Extract entity mentions from the research text. Output JSON:
{ "mentions": [ { "surface": "...", "type": "org"|"person"|"geo"|"site"|"product"|"vessel_class"|"route"|"market"|"regime"|"project"|"evidence"|null,
  "subtype": "string or null", "claim_refs": ["id1"], "context_hints": { "iso2Hint": "ae|null", "sectorHint": "...", "asOfHint": "..." },
  "per_claim_confidence": 0.0-1.0 } ] }

Rules:
- Use only the listed type values or null if no fit.
- subtype must be a short snake_case hint (e.g. private_holdco, port, ubo) or null.
- claim_refs must reference provided claim node ids only.
- Do not invent new type strings.

COVERAGE RULES (you MUST emit a mention for each of these when the text names them — not only named orgs):

product — class-level commodity or product line:
  - any commodity named on a supply route (e.g. "crude oil", "iron ore", "LNG", "coal",
    "copper concentrate", "refined tin", "palm oil", "wheat", "containerized goods"),
  - any product line in a catalog sense (e.g. "Model S", "Megapack", "iPhone"),
  - prefer class-level surface (strip SKU qualifiers like "Plaid", "Long Range", "Pro Max",
    years); put the raw variant in claim_refs text (the canonicalizer tracks variants).
  subtype examples: hydrocarbon, ore, bulk_dry, bulk_liquid, container, grain, refined_metal.

regime — normative / risk / governance regime that actors or sites are subject to or exposed to:
  - piracy zones ("Malacca piracy surge"),
  - war-risk areas ("war-risk premium area", "listed war-risk zone"),
  - sanctions / export-control regimes ("US OFAC sanctions", "EU 14th package",
    "UK trade sanctions", "export control regime on GaN"),
  - emission / environmental regimes ("IMO 2020 sulfur cap", "CII rating", "EU ETS for shipping"),
  - insurance / price regimes ("P&I club rules", "Brent benchmark", "FOB pricing regime"),
  - legal / jurisdictional regimes ("FCPA", "DOJ consent decree", "ADGM Court regime").
  subtype examples: piracy, war_risk_area, sanctions, export_control, emission, insurance, benchmark.

vessel_class — use SINGULAR surface where possible (e.g. "VLCC" not "VLCCs", "Valemax" not "Valemaxes").
  subtype examples: vlcc, vloc, suezmax, malaccamax, capesize, panamax, ulcv, feeder.

route — corridor / strait / canal / lane as a whole (distinct from a specific site).
  subtype examples: strait, canal, corridor, lane, rail_corridor, pipeline.

site — a specific named port/terminal/plant/mine/warehouse (e.g. "Port Klang", "Tuas Mega Port",
  "Phillip Channel" if modeled as a chokepoint site). Prefer site over route when the text
  talks about a specific terminal rather than the whole corridor.

market — exchange / benchmark venue ("Nasdaq", "LME", "Shanghai Futures Exchange", "TTF hub").

org — includes regulators (OFAC, IMO, MARAD), exchanges as legal entities (NYSE Group),
  liner alliances ("Ocean Alliance", "Gemini Cooperation"), miners, shippers, charterers.
  For regulators set subtype=regulator.

HARD RULE — no orphan attribute labels:
  If the text names a commodity in a supply context (e.g. "tankers carrying crude oil",
  "iron ore flows to China") you MUST emit a product mention. Same for regimes
  (piracy, war-risk, sanctions, emission caps). The canonicalizer will otherwise reject
  the surrounding edge as "unresolved endpoint surface".

HARD RULE — Incoterm codes are NEVER entities:
  The Incoterm codes CIF, FOB, CFR, FCA, DAP, EXW, DDP, DPU, FAS, CIP, CPT
  (including variants like "CIF China", "FOB Singapore") are NOT regime, NOT market,
  NOT product, NOT anything. They are edge-attribute values on supplies/charters
  (attributes.incoterm). DO NOT emit them as standalone mentions under any type.
  If you encounter one, silently skip it — the downstream layer will attach it to
  the relevant edge from the surrounding narrative.
