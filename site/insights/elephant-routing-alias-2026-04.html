Field Report · Model Provenance · 2026-04-18

A stealth model is a routing alias. And at frontier scale, models diverge.

Eleven models on the same TSMC / ASML / CHIPS Act session pack, under a strict-JSON critic contract. Two findings worth publishing — both counter to the standard "scale → consensus → truth" narrative — emerged from one afternoon of runs.

What this report is

Report #1 of our Horde.Vision Insights series — short field reports where we run the same prompt harness across paid and free LLMs on real industrial scenarios and publish the rubric-scored depth, cost, and per-model quirks. This one runs the same prompt seven times against an anonymized "stealth" slot on OpenRouter, then against ten named frontier and fast flagships. Two findings: a stealth model is not always a model (it can be a routing alias over several backends), and at frontier scale models diverge in judgment rather than converging on one answer.

TL;DR
  • Stealth ≠ single model. openrouter/elephant-alpha, run 7 times on identical input, produced two structurally distinct output styles and a 15× latency spread (2.0s → 30.3s). It is a routing alias, not a model.
  • Composition flips on the same prompt: stop ×5, conditional ×1, go ×2. Single-shot evaluations of stealth aliases cannot be trusted.
  • Frontier models diverge in judgment. 5 fast flagships agreed 5/5 on conditional. 5 frontier models split 3 stop / 1 conditional / 1 go — on the same prompt. Scale gives polarity, not consensus.
  • Industrial depth ladder is real: only claude-opus-4.7 surfaced ZEISS as the EUV-optics monopoly and named Wassenaar vs BIS/EAR as separate regulatory regimes. No fast model and neither Elephant backend reached that depth.

Finding 1 — A stealth alias is a routing alias over multiple backends

We started with a hypothesis. openrouter/elephant-alpha is an unattributed free model that, in our first paid-flagship batch, landed cleanly inside the speed-quality cluster of gpt-5.4-mini and claude-haiku-4.5. That made us suspect it might be a stealth-tier release of a western lab — possibly a quiet fork run for human-preference data collection on OpenRouter.

Then we noticed the same prompt produced different verdicts in two adjacent runs. We launched five isolated repeats. The result broke the hypothesis open.

Why "two backends" is the parsimonious explanation

Mode A blockers look like single_points_of_failure_not_explicitly_flagged — snake_case identifiers, no full sentences, no named companies, ~150–210 output tokens, latency reliably 2.0–2.7s.

Mode B blockers look like "Missing explicit dependencies between TSMC, ASML, Samsung, Intel, SMIC and Japanese/Dutch equipment vendors in design and lithography layers." Full prose, specific entities, ~210–285 output tokens, latency variable up to 30s.

The stylistic distance is too large for temperature variance inside one model. Temperature shifts word choice within a style. It does not toggle between two structurally different output formats. The simplest explanation is that elephant-alpha is an A/B routing alias over a pool — possibly a staged rollout, possibly preference-data collection under one brand. We do not know which. We do know the contract "one alias → one behavior" is not honored.

Implication for production. A critic that returns stop, conditional, and go on the same prompt cannot serve as a deterministic gate in any agent pipeline. Variance in judgment is too high. Speed leadership is preserved (~2s in 86% of runs), but the reliability contract is not.

Finding 2 — At frontier scale, judgment polarizes

We expected the opposite. The standard narrative says scale produces consensus: bigger models converge on the right answer. On this pack, the data goes the other way.

Fast-flagship critics hedged toward the safe middle: conditional, all of them, every time. Frontier critics had stronger opinions and did not align. Read carefully: this is not a hallucination story. All six frontier-batch models correctly identified the pack as sufficient: false. They simply disagreed about what to do next.

For multi-agent design this matters: a frontier critic raises the probability of opposition to other agents' decisions. That is sometimes the point — productive disagreement is the entire purpose of a critic role. But it must be planned for, not discovered after the fact when a stop verdict halts a job.

What we did not measure

  • Mode A vs Mode B distribution on prompts other than semiconductor. The bimodal split is firm only on this pack. On other packs the routing weights may be different.
  • Probability of each backend mode. Five replicates is enough to show the split exists, not enough to estimate proportions reliably.
  • Provider-side request IDs that might pin Elephant routing to a specific backend. Some providers expose this via headers; we did not capture it on this run.
  • Direct semantic similarity between Mode A and Mode B outputs (embeddings comparison). The qualitative split is obvious from reading; quantifying it is future work.
  • Long-context behavior, multi-turn, or tool-calling. Critic role only, single turn.

Interpretation

Where the leaderboard view fails

On a public leaderboard, elephant-alpha would be recorded as the speed-quality champion of free models on this pack. That ranking is true for any single run, and useless for picking a critic. The relevant metric for an agentic pipeline is behavior consistency across replicates on the same input; on that axis Elephant fails the contract entirely.

Symmetrically, Sonnet 4.6 and Opus 4.7 look "slow" on a latency chart (24–35s vs 2s for Elephant) and would lose a "speed of first token" comparison badly. They earn that latency on this pack: Opus is the only model that surfaces ZEISS, Sonnet is the only model that cites graph node IDs. For the critic role on a graph-based pipeline these are exactly the behaviors that pay the latency back later in fewer wasted cycles.

Failure modes by class, not by model

From this and the two adjacent April reports, we have started a typology of critic failure modes that is more useful than a per-model verdict:

  • Composition inversion — model says sufficient: false with non-zero blockers and still recommends go. Seen on nemotron-3-nano-30b, intermittently on Elephant Mode A.
  • Schema-drop under thinking pressure — provider goes into hidden chain-of-thought and returns empty content under strict schema. Seen consistently on z-ai/glm-4.5-air and glm-4.7-flash. This is a vendor-level pattern, not a single model fault.
  • Hidden-reasoning waste — output token count vastly exceeds final structured-output content (grok-4.1-fast burned 962 out tokens on a 780-character verdict). Cost is real, value to the downstream graph is zero.
  • Routing-alias polysemy — single model name returns structurally distinct outputs across calls. Seen on elephant-alpha. Disqualifies the alias from any deterministic gate role.
  • Spec-compliance drift across turns — not measured here (single-turn only) but the failure class is named for the v1 multi-turn report.

Practical implication

We do not recommend a model. The vision document is explicit on this. What we do recommend is a methodological habit: stealth and anonymous models should be evaluated at n ≥ 5 per (prompt × alias), and the median plus variance should be published separately. Single-shot evaluations of stealth aliases should be flagged "n=1, provenance unknown, treat as preview". For named production models the bar is lower — n=1 is acceptable for headline comparisons — but calibration variance still deserves a quarterly check.

For multi-agent designers, the second finding has a sharper edge. If your pipeline depends on a critic's verdict to gate expensive downstream work, the critic's tendency to oppose under ambiguity is a feature you select for, not a bug you discover. Frontier critics will produce stop more often than fast critics, even when fast critics agree. If "ship more, halt less" is your operating preference, a fast-tier conditional majority is the safer choice. If "halt early, defer hard" is the point of having a critic at all, frontier divergence is the actual signal you came for.

What we read this against

The five undermeasured directions visible in recent system cards from frontier labs — faithfulness of chain-of-thought, specification compliance under pressure, tool calibration, refusal asymmetry, and temporal calibration — all point at behavior that public benches like Artificial Analysis or LMSYS do not separate. This report is one small instance of why such separation matters: schema-drop, composition inversion, and routing-alias polysemy are all invisible to a one-shot "intelligence rank".

Reproduction

The two commands we ran, in shape. The harness script (bench_critic_models.py), the session pack it consumes (TSMC / ASML / CHIPS Act), and the raw JSONL outputs referenced in every table above live in a private research repo. We send them on request — see Artifacts below.

Frontier batch (one shot per model):

# inside the research repo root:
python scripts/bench_critic_models.py \
  --jsonl-out results/critic_bench_frontier_vs_elephant.jsonl \
  --max-output-tokens 8192 --timeout 600 \
  --models \
    openrouter/elephant-alpha \
    anthropic/claude-sonnet-4.6 \
    anthropic/claude-opus-4.7 \
    google/gemini-3.1-pro-preview \
    openai/gpt-5.4 \
    z-ai/glm-5.1

Variance series (n=5 on Elephant alone):

for i in 1 2 3 4 5; do
  python scripts/bench_critic_models.py \
    --jsonl-out results/elephant_variance_$i.jsonl \
    --max-output-tokens 4096 --timeout 120 \
    --models openrouter/elephant-alpha
  sleep 3
done

Expected variance on a rerun: latency ±30%, mode distribution ±2 of 5. Composition will differ across runs on Elephant — that is the entire point of the report. If your rerun produces stable composition, OpenRouter has changed the routing behind the alias since we published.
