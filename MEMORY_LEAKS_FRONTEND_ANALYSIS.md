# Анализ утечек памяти на фронтенде

## Найденные и исправленные проблемы

### 1. ✅ AuthContext.tsx - setTimeout без cleanup

**Проблема:**
В `useEffect` использовался `setTimeout` для задержки загрузки подписки, но таймер не очищался при размонтировании компонента.

**Исправление:**
- Добавлен `useRef` для хранения ID таймера
- Таймер очищается в cleanup функции `useEffect`
- Таймер также очищается при изменении пользователя

**Файл:** `web/src/contexts/AuthContext.tsx`

### 2. ✅ genaiChatStore.ts - Рекурсивные setTimeout в waitForAgentCompletion

**Проблема:**
Функция `waitForAgentCompletion` использовала рекурсивные `setTimeout` для опроса статуса агента, но таймеры не отслеживались и не очищались при:
- Смене проекта
- Размонтировании компонента
- Вызове `reset()`

**Исправление:**
- Добавлен `Map` для отслеживания активных таймеров агентов (`activeAgentTimers`)
- Каждый таймер сохраняется в Map с ключом `taskId`
- Таймеры проверяют актуальность `projectId` перед выполнением
- Добавлена функция `clearAllAgentTimers()` для очистки всех таймеров
- Добавлена функция `clearAgentTimersForProject()` для очистки при смене проекта
- Таймеры очищаются в `reset()` и `setProjectId()`

**Файл:** `web/src/stores/genaiChatStore.ts`

### 3. ✅ discoveryStore.ts - Улучшена очистка subscriptionWaiters

**Проблема:**
При закрытии WebSocket соединения (onclose/onerror) не всегда вызывалась очистка ожидающих подписок (`subscriptionWaiters`).

**Исправление:**
- Добавлен явный вызов `rejectAllSubscriptionWaiters()` в обработчиках `onclose` и `onerror`
- Это гарантирует, что все ожидающие подписки будут отклонены и очищены при любом закрытии соединения

**Файл:** `web/src/stores/discoveryStore.ts`

### 4. ℹ️ useWebSocketConnection.ts - Без изменений

**Анализ:**
Хук `useWebSocketConnection` просто вызывает `connectWs()` один раз при монтировании. WebSocket соединение управляется глобально в `discoveryStore` и правильно очищается через `cleanupDiscoveryStore()`. Утечки памяти здесь нет.

### ✅ Правильно реализованные cleanup функции:

1. **DiscoveryPage.tsx** - правильно очищает `setInterval` для таймера "Thinking..."
2. **UnfoldRequest.tsx** - правильно очищает все таймеры в cleanup функции
3. **PagesPanel.tsx** - правильно очищает `addEventListener` для resize
4. **SidebarPanel.tsx** - правильно очищает event listeners

### ⚠️ Потенциальные области для мониторинга:

1. **processedDoneEvents Set** в `discoveryStore.ts`:
   - Set очищается через 5 минут после добавления
   - Это нормально, но стоит следить за размером в production

2. **subscriptionWaiters Map** в `discoveryStore.ts`:
   - Теперь правильно очищается при закрытии WebSocket
   - Таймауты автоматически очищаются при resolve/reject

3. **pendingSubscriptions Map** в `discoveryStore.ts`:
   - Очищается в `finally` блоке после завершения подписки
   - Это безопасно
