# Agent Capabilities: Use Cases & Missing Implementations

## Текущие Capabilities (Реализованные)

### 1. `document_read` ✅
**Юзкейсы:**
- Чтение документов для анализа
- Получение содержимого для обработки
- Валидация доступа к документам

### 2. `document_write` ✅
**Юзкейсы:**
- Сохранение результатов анализа
- Обновление документов после обработки
- Создание новых документов

### 3. `data_search` ✅
**Юзкейсы:**
- Поиск документов по запросу
- Фильтрация по tenantId и projectId
- Поиск релевантной информации в проекте

### 4. `web_search` ✅
**Юзкейсы:**
- Поиск информации в интернете
- Верификация фактов
- Получение актуальных данных

### 5. `llm_generate` ✅
**Юзкейсы:**
- Генерация текста
- Создание резюме
- Генерация контента

### 6. `llm_analyze` ✅
**Юзкейсы:**
- Структурированный анализ данных
- Извлечение структурированной информации
- Классификация контента

### 7. `bigquery_query` ✅
**Юзкейсы:**
- Выполнение SQL запросов
- Анализ данных в BigQuery
- Получение метаданных документов

## Объявленные, но не реализованные Capabilities

### 8. `data_enhancement` ❌
**Потенциальные юзкейсы:**
- Очистка и нормализация данных
- Обогащение данных дополнительной информацией
- Валидация качества данных
- Заполнение пропусков в данных
- Стандартизация форматов

**Примеры:**
- Очистка CSV от дубликатов
- Нормализация названий компаний
- Добавление геолокации к адресам
- Валидация email адресов

### 9. `entity_extract` ❌
**Потенциальные юзкейсы:**
- Извлечение сущностей из текста (люди, компании, места)
- Связывание сущностей с существующими в системе
- Обогащение сущностей дополнительными данными
- Построение графа связей

**Примеры:**
- Извлечение упоминаний компаний из документов
- Поиск связей между сущностями
- Обогащение сущностей данными из внешних источников

### 10. `event_create` ❌
**Потенциальные юзкейсы:**
- Создание событий на основе анализа документов
- Автоматическое определение временных меток
- Связывание событий с сущностями
- Классификация событий по типам

**Примеры:**
- Создание событий из новостных статей
- Определение важных дат в документах
- Связывание событий с участниками

### 11. `artifact_create` ❌
**Потенциальные юзкейсы:**
- Создание артефактов (entities.json, facts.json, events.json, metrics.json, decisions.json)
- Автоматическая генерация структурированных данных
- Обновление существующих артефактов
- Валидация структуры артефактов

**Примеры:**
- Генерация entities.json из документов
- Создание facts.json на основе анализа
- Обновление metrics.json с новыми данными

## Приоритетные для реализации

### Высокий приоритет:
1. **`entity_extract`** - уже есть `AnalyzeEntities`, нужно интегрировать
2. **`artifact_create`** - уже есть `CreateArtifact`, нужно интегрировать
3. **`event_create`** - уже есть `AnalyzeEvents`, нужно интегрировать
4. **`data_enhancement`** - полезно для подготовки данных
5. **`document_summarize`** - часто используемый юзкейс

### Средний приоритет:
6. **`data_aggregate`** - полезно для объединения результатов
7. **`data_validate`** - важно для качества данных
8. **`document_compare`** - полезно для версионирования
9. **`document_classify`** - улучшает организацию документов
10. **`data_export`** - важно для экспорта результатов

### Низкий приоритет:
11. **`document_translate`** - зависит от требований
12. **`notification_send`** - можно реализовать через существующие механизмы
13. **`file_upload/download`** - частично реализовано через документы
14. **`temporal_analysis`** - можно через BigQuery
15. **`duplicate_detect`** - можно через data_search
16. **`external_api_call`** - зависит от конкретных интеграций
17. **`visualization_generate`** - можно делегировать фронтенду

## Рекомендации

1. **Интегрировать существующие функции** - `AnalyzeEntities`, `AnalyzeEvents`, `CreateArtifact` уже реализованы, нужно создать соответствующие capabilities
2. **Начать с высокоприоритетных** - `entity_extract`, `artifact_create`, `event_create` имеют готовую логику
3. **Использовать композицию** - многие юзкейсы можно реализовать через комбинацию существующих capabilities
4. **Добавить по мере необходимости** - не все capabilities нужны сразу, добавлять по запросу
