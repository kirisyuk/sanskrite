# Возможности режима Analytics

Режим Analytics позволяет выполнять запросы на естественном языке к документам проекта через BigQuery. Ниже перечислены типы запросов, которые поддерживаются.

## 📊 Доступные данные

### Таблицы метаданных:
- **`core_docs_metadata`** - метаданные всех документов проекта:
  - `id`, `filename`, `contentType`, `description`, `sizeBytes`
  - `storagePath`, `extractedText`, `parseStatus`, `parseMeta` (JSON)
  - `pageCount`, `docType`, `createdBy`, `createdAt`, `updatedAt`
  - Автоматически фильтруется по `projectId` и `tenantId`

- **`documents_metadata`** - метаданные RAG документов:
  - `id`, `title`, `url`, `documentPath`, `storagePath`
  - `status`, `contentType`, `documentType`, `language`
  - `ingestedAt`, `createdAt`, `updatedAt`

### Object Tables (прямое чтение из GCS):
- **`core_docs_text_table`** - текстовые файлы (.txt, .md, .csv, .tsv)
- **`core_docs_json_table`** - JSON файлы
- **`documents_object_table`** - RAG документы (.txt)

## 🔍 Типы запросов

### 1. Анализ метаданных документов

**Примеры:**
- "Сколько документов в проекте?"
- "Покажи все CSV файлы"
- "Какие документы были загружены за последний месяц?"
- "Найди все PDF документы больше 1MB"
- "Сколько страниц во всех документах проекта?"
- "Покажи документы, отсортированные по дате создания"

**Что можно анализировать:**
- Количество документов по типам
- Размеры файлов (агрегация, среднее, максимум)
- Даты создания/обновления
- Статусы парсинга
- Типы документов (docType)

### 2. Анализ содержимого CSV файлов

**Примеры:**
- "Покажи первые 10 строк из CSV файла data123.csv"
- "Какие колонки есть в CSV файлах проекта?"
- "Посчитай сумму по колонке 'sales' в CSV"
- "Найди максимальное значение в колонке 'revenue'"
- "Сгруппируй данные по дате и посчитай среднее"
- "Покажи уникальные значения в колонке 'category'"

**Особенности:**
- CSV читается через `core_docs_text_table` Object Table
- Можно парсить через `SPLIT()` или `REGEXP` функции
- Можно создавать временные таблицы через `WITH` clauses
- Поддержка агрегаций, группировок, сортировок

### 3. Прогнозирование и временные ряды

**Примеры:**
- "Спрогнозируй продажи на следующие 30 дней"
- "Создай модель для предсказания тренда"
- "Покажи прогноз на основе исторических данных"
- "Проанализируй тренд за последний год"

**Технологии:**
- **ARIMA_PLUS** - для временных рядов
- **LINEAR_REG** - для линейной регрессии
- **XGBOOST** - для сложных моделей
- Автоматическое создание моделей через `CREATE MODEL`
- Прогнозы через `ML.FORECAST()` и `ML.PREDICT()`

**Пример SQL (генерируется автоматически):**
```sql
CREATE MODEL `project.forecast_model`
OPTIONS(model_type='ARIMA_PLUS', horizon=30) AS
SELECT date, sales FROM ...
WHERE projectId = @projectId
```

### 4. Анализ текстового содержимого

**Примеры:**
- "Найди все документы, содержащие слово 'продажи'"
- "Покажи документы с наибольшим количеством текста"
- "Найди документы, где упоминается '2024'"
- "Посчитай частоту слов в документах"

**Доступ к тексту:**
- `extractedText` поле в `core_docs_metadata`
- Прямое чтение через Object Tables
- Использование `CONTAINS`, `LIKE`, `REGEXP_CONTAINS`
- Анализ через BigQuery ML функции

### 5. Анализ JSON документов

**Примеры:**
- "Извлеки поле 'total' из всех JSON файлов"
- "Покажи структуру JSON документов"
- "Найди все JSON файлы с полем 'status' = 'active'"
- "Агрегируй данные из JSON по полю 'category'"

**Функции:**
- `JSON_EXTRACT_SCALAR()` - для скалярных значений
- `JSON_EXTRACT()` - для объектов/массивов
- `PARSE_JSON()` - для парсинга JSON строк
- Чтение через `core_docs_json_table`

### 6. Статистический анализ

**Примеры:**
- "Посчитай среднее, медиану и стандартное отклонение"
- "Покажи распределение данных по категориям"
- "Найди выбросы в данных"
- "Создай сводную таблицу (pivot table)"

**Функции BigQuery:**
- `AVG()`, `SUM()`, `COUNT()`, `MIN()`, `MAX()`
- `STDDEV()`, `VARIANCE()`, `PERCENTILE_CONT()`
- `PIVOT` для сводных таблиц
- `UNNEST()` для работы с массивами

### 7. Создание временных таблиц и сохранение результатов

**Примеры:**
- "Создай таблицу с результатами анализа"
- "Сохрани прогноз в новую таблицу"
- "Создай сводную таблицу по категориям"

**Возможности:**
- `CREATE TABLE AS SELECT` (CTAS)
- `WITH` clauses для временных таблиц
- Сохранение результатов для дальнейшего анализа

### 8. Комплексные аналитические запросы

**Примеры:**
- "Сравни продажи по месяцам за последний год"
- "Найди корреляцию между двумя метриками"
- "Покажи топ-10 документов по размеру"
- "Создай отчет по всем CSV файлам проекта"

**Особенности:**
- Поддержка JOIN между таблицами
- Подзапросы и CTEs (WITH clauses)
- Оконные функции (window functions)
- Сложные агрегации с GROUP BY

## 🚫 Ограничения

### Что НЕ поддерживается:
- ❌ Модификация данных (только чтение)
- ❌ Удаление документов
- ❌ Загрузка новых файлов через BigQuery
- ❌ Прямое редактирование CSV (только анализ)
- ❌ Работа с бинарными форматами (изображения, видео)

### Что требует дополнительной настройки:
- ⚠️ Для работы с CSV нужна правильная структура данных
- ⚠️ Большие файлы (>100MB) могут работать медленно
- ⚠️ ML модели требуют достаточного объема данных для обучения

## 💡 Рекомендации по использованию

### Для CSV анализа:
1. Убедитесь, что CSV файлы имеют заголовки
2. Используйте четкие названия колонок
3. Для временных рядов - убедитесь, что есть колонка с датами

### Для прогнозирования:
1. Нужны исторические данные (минимум 30-50 точек)
2. Укажите горизонт прогноза (например, "на 30 дней")
3. Укажите метрику для прогноза (например, "продажи", "объемы")

### Для текстового анализа:
1. Используйте конкретные ключевые слова
2. Учитывайте, что поиск чувствителен к регистру (можно использовать UPPER/LOWER)
3. Для больших документов используйте LIMIT

## 🔧 Технические детали

- **Фильтрация:** Автоматическая по `projectId` и `tenantId`
- **Лимиты:** По умолчанию 100 строк (можно изменить через `maxResults`)
- **Формат ответа:** SQL запрос + объяснение + результаты в таблице
- **Логирование:** Все шаги логируются для отладки
