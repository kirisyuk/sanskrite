# CR-001: Избежание дублирования сообщений анализа чата при добавлении источника

## Описание

При добавлении нового источника в существующий проект бэкэнд не должен отправлять повторное сообщение с анализом чата в Telegram. В настоящее время система отправляет сообщение с анализом каждый раз при добавлении источника, что создает дублирование и может раздражать пользователей.

## Проблема

- При добавлении источника в проект система отправляет сообщение с анализом чата
- Если в проекте уже есть источники, повторная отправка анализа создает дублирование информации
- Пользователи получают избыточные уведомления

## Требования

1. **Проверка существующих источников**: Перед отправкой сообщения с анализом чата система должна проверить, есть ли уже источники в проекте
2. **Условная отправка**: Сообщение с анализом должно отправляться только если:
   - Это первый источник в проекте
   - Или если пользователь явно запросил повторный анализ
3. **Сохранение функциональности**: Все остальные уведомления (о статусе обработки, ошибках и т.д.) должны продолжать работать как прежде

## Технические детали

### Затронутые компоненты

- `backend/internal/discovery/orchestrator.go` - основная логика обработки источников
- `backend/internal/telegram/client.go` - отправка сообщений в Telegram
- `backend/internal/http/discovery.go` - API endpoints для работы с источниками

### Предлагаемая реализация

1. **Добавить проверку в orchestrator**:
   ```go
   // Проверить количество существующих источников в проекте
   existingSourcesCount := repo.GetSourcesCountByProjectID(projectID)
   if existingSourcesCount == 0 {
       // Отправить сообщение с анализом чата только для первого источника
       sendChatAnalysisMessage(projectID, sourceID)
   }
   ```

2. **Модифицировать логику отправки сообщений**:
   - Добавить параметр `isFirstSource` в функции отправки сообщений
   - Условно отправлять анализ чата только для первого источника

3. **Обновить API**:
   - Возможно, добавить опциональный параметр `forceAnalysis` для принудительного анализа

## Критерии приемки

- [ ] При добавлении первого источника в проект отправляется сообщение с анализом чата
- [ ] При добавлении последующих источников в тот же проект сообщение с анализом НЕ отправляется
- [ ] Все остальные уведомления (статус обработки, ошибки) продолжают работать
- [ ] Существует способ принудительно запросить анализ чата (опционально)
