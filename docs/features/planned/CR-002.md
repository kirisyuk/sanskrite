# CR-002: Система учёта расходов на AI по прайс-листам

## Описание

Реализовать комплексную систему учёта расходов на использование AI-моделей различных провайдеров (OpenAI, Claude, Gemini, Grok) с детализацией по моделям, задачам и пользователям. Система должна предоставлять точную аналитику расходов, прогнозирование бюджета и контроль лимитов.

## Проблема

В настоящее время система использует множество AI-провайдеров с различными моделями и ценами, но отсутствует централизованный учёт расходов:

- Нет детального отслеживания расходов по провайдерам и моделям
- Отсутствует аналитика использования AI по пользователям и проектам
- Нет системы контроля лимитов и бюджетирования
- Сложно прогнозировать расходы на основе исторических данных
- Отсутствует возможность оптимизации выбора моделей на основе стоимости

## Требования

### 1. Детальный учёт расходов
- Отслеживание расходов по каждому AI-запросу с указанием:
  - Провайдера и модели
  - Количества входных и выходных токенов
  - Стоимости по прайс-листу провайдера
  - Времени выполнения запроса
  - Типа задачи (анализ, генерация, поиск и т.д.)
  - Пользователя и проекта

### 2. Агрегация и аналитика
- Группировка расходов по различным измерениям:
  - По провайдерам (OpenAI, Claude, Gemini, Grok)
  - По моделям (gpt-4o, claude-sonnet-4, gemini-2.5-flash и т.д.)
  - По пользователям и проектам
  - По типам задач
  - По временным периодам (день, неделя, месяц)

### 3. Контроль лимитов и бюджетирование
- Установка лимитов расходов на уровне:
  - Пользователя
  - Проекта
  - Тенанта (организации)
- Уведомления при приближении к лимитам
- Автоматическая остановка при превышении критических лимитов

### 4. Прогнозирование и оптимизация
- Прогноз расходов на основе исторических данных
- Рекомендации по оптимизации выбора моделей
- Анализ эффективности использования различных провайдеров

#### 1. Модели данных

```go
// AIUsageRecord записывает каждый AI-запрос с деталями стоимости
type AIUsageRecord struct {
    ID              string    `json:"id" firestore:"id"`
    TenantID        string    `json:"tenantId" firestore:"tenantId"`
    UserID          string    `json:"userId" firestore:"userId"`
    ProjectID       *string   `json:"projectId,omitempty" firestore:"projectId"`
    
    // AI детали
    Provider        string    `json:"provider" firestore:"provider"`
    Model           string    `json:"model" firestore:"model"`
    TaskType        string    `json:"taskType" firestore:"taskType"`
    
    // Токены и стоимость
    InputTokens     int       `json:"inputTokens" firestore:"inputTokens"`
    OutputTokens    int       `json:"outputTokens" firestore:"outputTokens"`
    TotalTokens     int       `json:"totalTokens" firestore:"totalTokens"`
    
    // Стоимость (в USD)
    InputCost       float64   `json:"inputCost" firestore:"inputCost"`
    OutputCost      float64   `json:"outputCost" firestore:"outputCost"`
    TotalCost       float64   `json:"totalCost" firestore:"totalCost"`
    
    // Метаданные
    ProcessingTime  time.Duration `json:"processingTime" firestore:"processingTime"`
    Success        bool      `json:"success" firestore:"success"`
    ErrorMessage   *string   `json:"errorMessage,omitempty" firestore:"errorMessage"`
    
    CreatedAt       time.Time `json:"createdAt" firestore:"createdAt"`
}

// AIUsageLimit лимиты расходов
type AIUsageLimit struct {
    ID              string    `json:"id" firestore:"id"`
    TenantID        string    `json:"tenantId" firestore:"tenantId"`
    Scope           string    `json:"scope" firestore:"scope"` // user|project|tenant
    ScopeID         string    `json:"scopeId" firestore:"scopeId"`
    
    // Лимиты
    DailyLimit      *float64  `json:"dailyLimit,omitempty" firestore:"dailyLimit"`
    MonthlyLimit    *float64  `json:"monthlyLimit,omitempty" firestore:"monthlyLimit"`
    TotalLimit      *float64  `json:"totalLimit,omitempty" firestore:"totalLimit"`
    
    // Уведомления
    WarningThreshold float64   `json:"warningThreshold" firestore:"warningThreshold"` // 0.8 = 80%
    AlertEmails     []string  `json:"alertEmails,omitempty" firestore:"alertEmails"`
    
    CreatedAt       time.Time `json:"createdAt" firestore:"createdAt"`
    UpdatedAt       time.Time `json:"updatedAt" firestore:"updatedAt"`
}

// AIUsageStats агрегированная статистика
type AIUsageStats struct {
    Period          string    `json:"period" firestore:"period"` // day|week|month|year
    StartDate       time.Time `json:"startDate" firestore:"startDate"`
    EndDate         time.Time `json:"endDate" firestore:"endDate"`
    
    // Общие метрики
    TotalRequests   int       `json:"totalRequests" firestore:"totalRequests"`
    TotalTokens     int       `json:"totalTokens" firestore:"totalTokens"`
    TotalCost       float64   `json:"totalCost" firestore:"totalCost"`
    AvgCostPerRequest float64 `json:"avgCostPerRequest" firestore:"avgCostPerRequest"`
    
    // По провайдерам
    ProviderStats   map[string]ProviderStats `json:"providerStats" firestore:"providerStats"`
    
    // По моделям
    ModelStats      map[string]ModelStats `json:"modelStats" firestore:"modelStats"`
    
    // По пользователям
    UserStats       map[string]UserStats `json:"userStats" firestore:"userStats"`
}

type ProviderStats struct {
    Requests        int       `json:"requests"`
    Tokens          int       `json:"tokens"`
    Cost            float64   `json:"cost"`
    AvgCostPerToken float64   `json:"avgCostPerToken"`
}

type ModelStats struct {
    Requests        int       `json:"requests"`
    Tokens          int       `json:"tokens"`
    Cost            float64   `json:"cost"`
    AvgProcessingTime time.Duration `json:"avgProcessingTime"`
}

type UserStats struct {
    Requests        int       `json:"requests"`
    Tokens          int       `json:"tokens"`
    Cost            float64   `json:"cost"`
    Projects        []string  `json:"projects"`
}
```

#### 2. Интеграция с существующей системой

```go
// В AITaskExecutor.ExecuteTask добавить запись использования
func (e *AITaskExecutor) ExecuteTask(ctx context.Context, task *AITask) (*AITaskResult, error) {
    // ... существующая логика ...
    
    // После успешного выполнения
    if result.Status == AITaskStatusCompleted {
        // Записать использование в базу данных
        usageRecord := &AIUsageRecord{
            TenantID:      task.TenantID,
            UserID:        task.UserID,
            ProjectID:      task.ProjectID,
            Provider:      string(modelCapabilities.Provider),
            Model:         currentModel,
            TaskType:      string(task.TaskType),
            InputTokens:   result.InputTokens,
            OutputTokens:  result.OutputTokens,
            TotalTokens:   result.InputTokens + result.OutputTokens,
            InputCost:     float64(result.InputTokens) * modelCapabilities.PricePerInputToken,
            OutputCost:    float64(result.OutputTokens) * modelCapabilities.PricePerOutputToken,
            TotalCost:     result.ProcessingCost,
            ProcessingTime: result.ProcessingTime,
            Success:       true,
            CreatedAt:     time.Now(),
        }
        
        // Сохранить в репозитории
        err := e.usageRepo.CreateUsageRecord(ctx, usageRecord)
        if err != nil {
            log.Printf("Failed to record AI usage: %v", err)
        }
        
        // Проверить лимиты
        e.checkUsageLimits(ctx, usageRecord)
    }
    
    return result, nil
}
```

## Критерии приемки

### Функциональные требования
- [ ] Каждый AI-запрос записывается с полными деталями стоимости
- [ ] Доступна детализированная статистика по всем измерениям
- [ ] Работает система лимитов с уведомлениями
- [ ] Реализован прогноз расходов на основе исторических данных
- [ ] API предоставляет все необходимые endpoints для аналитики

### Производительность
- [ ] Запись использования не замедляет выполнение AI-задач
- [ ] Агрегация статистики выполняется эффективно
- [ ] Frontend отображает данные без задержек

### Точность
- [ ] Расчёт стоимости соответствует прайс-листам провайдеров
- [ ] Агрегированная статистика математически корректна
- [ ] Прогнозы основаны на достаточном объёме исторических данных

### Пользовательский опыт
- [ ] Дашборд интуитивно понятен и информативен
- [ ] Уведомления о лимитах своевременны и не навязчивы
- [ ] Возможность экспорта данных в различных форматах
