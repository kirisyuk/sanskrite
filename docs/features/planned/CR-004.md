# CR-004: Интерактивные сообщения с выбором области действия команд

## Описание

Реализовать систему интерактивных сообщений чат-бота, которые реагируют на команды пользователя (например, "/analyze entities", "/process summarize") и позволяют интерактивно выбрать область применения команды - последнее сообщение, текущая секция/ветка, весь чат, или определённый диапазон сообщений.

## Проблема

В текущей системе команды чата применяются автоматически к сообщению, из которого была отправлена команда, или к некоему контексту по умолчанию. Это создаёт ограничения:

- Невозможно применить команду к группе сообщений или всей ветке обсуждения
- Отсутствует гибкость выбора области действия команды
- Пользователю приходится повторно отправлять команды для разных контекстов
- Нет явного подтверждения того, к чему будет применена команда

Пример ситуации:
- Пользователь хочет распознать все сущности из целой ветки обсуждения
- Текущая система может распознать только сущности из последнего сообщения
- Приходится вручную копировать текст и обрабатывать по частям

## Требования

### 1. Интерактивные сообщения с кнопками выбора

Система должна генерировать интерактивные сообщения с кнопками выбора области действия:

```
🤖 Команда: /analyze entities

Выберите область для анализа:

[📝 Последнее сообщение]
[🌿 Вся текущая ветка]
[💬 Весь чат]
[📋 Указать диапазон]

🔍 Или введите тип анализа: entities, metrics, events, facts, decisions
```

### 2. Типы команд с выбором области

**Универсальные команды с параметрами:**

#### Аналитика - `/analyze <тип>`
Универсальная команда для аналитических операций с параметром типа анализа:
- `/analyze entities` - распознать сущности
- `/analyze metrics` - извлечь метрики
- `/analyze events` - найти события
- `/analyze facts` - обнаружить факты
- `/analyze decisions` - определить решения
- `/analyze` - автоматическое определение типа анализа через AI

#### Обработка - `/process <тип>`
Универсальная команда для обработки текста с параметром типа обработки:
- `/process summarize` - суммировать контент
- `/process translate` - перевести
- `/process rephrase` - переформулировать
- `/process expand` - расширить/детализировать
- `/process` - выбор типа обработки через меню

#### Структурирование - `/structure <тип>`
Универсальная команда для создания структурированных артефактов:
- `/structure document` - создать документ
- `/structure table` - создать таблицу
- `/structure list` - построить список
- `/structure topic-map` - организовать по темам
- `/structure` - выбор типа структурирования через меню

**Итого: 3 универсальные команды вместо 13+**

#### Преимущества универсального подхода
- **Меньше команд для запоминания** - 3 вместо 13+
- **Легче расширение** - новые типы добавляются как параметры
- **Автодополнение и подсказки** - система предлагает доступные типы
- **Единый интерфейс** - одинаковый UX для всех категорий команд
- **Интеллектуальный выбор** - AI может предложить подходящий тип при `/analyze` без параметра

#### Автодополнение команд
При вводе команды пользователь получает подсказки:
- `/analyze` → подсказки: entities, metrics, events, facts, decisions
- `/process` → подсказки: summarize, translate, rephrase, expand
- `/structure` → подсказки: document, table, list, topic-map

### 3. Режимы выбора области

#### Последнее сообщение
- Применяет команду только к сообщению, из которого была вызвана команда
- Моментальное выполнение (без дополнительных шагов)

#### Текущая ветка/секция
- Применяет команду ко всей ветке обсуждения
- Определяет ветку по структуре чата (ответы и под-ответы)
- Включает все сообщения в выбранной ветке

#### Весь чат
- Применяет команду ко всем сообщениям в текущем чате
- Может быть ограничено определённым временным периодом или количеством сообщений
- Показывает прогресс выполнения

#### Указанный диапазон
- Пользователь может выбрать конкретные сообщения
- Отображение временной шкалы или списка сообщений
- Multi-select интерфейс для выбора сообщений

### 4. Подтверждение и предпросмотр

Перед выполнением команды система должна показать:
- Какая область будет обработана
- Примерное количество сообщений/слов
- Ожидаемое время выполнения
- Предварительный результат (если возможно)

```
🤖 Область выбрана: Текущая ветка обсуждения

📊 Статистика:
• Сообщений: 12
• Слов: ~1,450
• Ожидаемое время: ~5 сек

Выполнить команду /analyze entities?

[✅ Подтвердить] [❌ Отменить] [🔍 Предпросмотр]
```

### 5. Прогресс выполнения

Для долгих операций должна отображаться информация о прогрессе:

```
🤖 Обработка: /analyze entities

📊 Прогресс: 5/12 сообщений

Распознано сущностей: 8
• Иван Иванов (person)
• Acme Corp (organization)
• Проект X (project)
...
```

// InteractiveMessage интерактивное сообщение с кнопками выбора
type InteractiveMessage struct {
    ID          string            `json:"id" firestore:"id"`
    UserID      string            `json:"userId" firestore:"userId"`
    ProjectID   string            `json:"projectId" firestore:"projectId"`
    
    // Исходная команда
    Command     string            `json:"command" firestore:"command"`           // полная команда: "/analyze entities"
    CommandCategory string         `json:"commandCategory" firestore:"commandCategory"` // analyze, process, structure
    CommandParams   string            `json:"commandParams" firestore:"commandParams"`  // entities, summarize, table, etc.
    
    // Состояние интерактивной сессии
    State       InteractiveState  `json:"state" firestore:"state"`
    Options     []MessageOption   `json:"options" firestore:"options"`
    SelectedOption *string         `json:"selectedOption,omitempty" firestore:"selectedOption"`
    
    // Результат команды
    Result      interface{}       `json:"result,omitempty" firestore:"result"`
    Status      string            `json:"status" firestore:"status"` // pending, processing, completed, cancelled
    
    CreatedAt   time.Time         `json:"createdAt" firestore:"createdAt"`
    UpdatedAt   time.Time         `json:"updatedAt" firestore:"updatedAt"`
}

// InteractiveState состояние интерактивной сессии
type InteractiveState string

const (
    InteractiveStateWaitingForSelection InteractiveState = "waiting_for_selection"
    InteractiveStateConfirming          InteractiveState = "confirming"
    InteractiveStateProcessing          InteractiveState = "processing"
    InteractiveStateCompleted           InteractiveState = "completed"
    InteractiveStateCancelled           InteractiveState = "cancelled"
)

// MessageOption опция выбора области
type MessageOption struct {
    ID          string   `json:"id" firestore:"id"`
    Label       string   `json:"label" firestore:"label"`
    Description string   `json:"description" firestore:"description"`
    Icon        string   `json:"icon" firestore:"icon"`
    Scope       string   `json:"scope" firestore:"scope"` // last_message, current_thread, entire_chat, custom_range
}

// MessageScope область применения команды
type MessageScope struct {
    Type      string   `json:"type" firestore:"type"` // last_message, current_thread, entire_chat, custom_range
    MessageIDs []string `json:"messageIds,omitempty" firestore:"messageIds"`
    StartDate *time.Time `json:"startDate,omitempty" firestore:"startDate"`
    EndDate   *time.Time `json:"endDate,omitempty" firestore:"endDate"`
    MaxMessages *int     `json:"maxMessages,omitempty" firestore:"maxMessages"`
}

// ChatThread ветка обсуждения
type ChatThread struct {
    RootMessageID    string        `json:"rootMessageId" firestore:"rootMessageId"`
    Messages         []ChatMessage `json:"messages" firestore:"messages"`
    ParticipantCount int           `json:"participantCount" firestore:"participantCount"`
    LastActivity     time.Time     `json:"lastActivity" firestore:"lastActivity"`
}

// InteractiveCommandService сервис для обработки интерактивных команд
type InteractiveCommandService struct {
    chatRepo       *ChatRepository
    aiService      AIService
    realtimeService *RealtimeService
}

// HandleCommand обрабатывает команду и создаёт интерактивное сообщение
func (s *InteractiveCommandService) HandleCommand(
    ctx context.Context,
    command string,
    userId, projectId string,
    messageId string,
) (*InteractiveMessage, error) {
    // 1. Парсинг команды
    parsed := s.parseCommand(command)
    
    // 2. Определить типы выбора области для команды
    options := s.getScopeOptions(parsed.Type)
    
    // 3. Создать интерактивное сообщение
    interactiveMsg := &InteractiveMessage{
        UserID:      userId,
        ProjectID:   projectId,
        Command:     command,
        CommandType: parsed.Type,
        State:       InteractiveStateWaitingForSelection,
        Options:     options,
        Status:      "pending",
        CreatedAt:   time.Now(),
        UpdatedAt:   time.Now(),
    }
    
    // 4. Сохранить и отправить через WebSocket
    id, err := s.chatRepo.CreateInteractiveMessage(ctx, interactiveMsg)
    if err != nil {
        return nil, err
    }
    interactiveMsg.ID = id
    
    // 5. Отправить клиенту через WebSocket
    s.realtimeService.SendInteractiveMessage(userId, interactiveMsg)
    
    return interactiveMsg, nil
}

// HandleOptionSelection обрабатывает выбор опции пользователем
func (s *InteractiveCommandService) HandleOptionSelection(
    ctx context.Context,
    messageId string,
    optionId string,
) (*InteractiveMessage, error) {
    // 1. Получить интерактивное сообщение
    msg, err := s.chatRepo.GetInteractiveMessage(ctx, messageId)
    if err != nil {
        return nil, err
    }
    
    // 2. Обновить выбранную опцию
    msg.SelectedOption = &optionId
    msg.State = InteractiveStateConfirming
    msg.UpdatedAt = time.Now()
    
    // 3. Получить область применения команды
    scope, preview, err := s.resolveScope(ctx, msg, optionId)
    if err != nil {
        return nil, err
    }
    
    // 4. Показать предпросмотр и подтверждение
    confirmation := &ConfirmationPreview{
        Scope:      scope,
        Stats:      preview,
        ExpectTime: s.estimateExecutionTime(msg.CommandType, scope),
    }
    
    // 5. Обновить и отправить
    s.chatRepo.UpdateInteractiveMessage(ctx, msg)
    s.realtimeService.SendConfirmationPreview(msg.UserID, msg, confirmation)
    
    return msg, nil
}

// HandleConfirmation обрабатывает подтверждение выполнения
func (s *InteractiveCommandService) HandleConfirmation(
    ctx context.Context,
    messageId string,
    confirmed bool,
) (*InteractiveMessage, error) {
    // 1. Получить сообщение
    msg, err := s.chatRepo.GetInteractiveMessage(ctx, messageId)
    if err != nil {
        return nil, err
    }
    
    if !confirmed {
        msg.State = InteractiveStateCancelled
        s.chatRepo.UpdateInteractiveMessage(ctx, msg)
        return msg, nil
    }
    
    // 2. Начать обработку
    msg.State = InteractiveStateProcessing
    msg.Status = "processing"
    s.chatRepo.UpdateInteractiveMessage(ctx, msg)
    
    // 3. Получить выбранные сообщения для обработки
    scope, _ := s.resolveScope(ctx, msg, *msg.SelectedOption)
    
    // 4. Выполнить команду асинхронно
    go s.executeCommandAsync(ctx, msg, scope)
    
    // 5. Отправить прогресс
    s.realtimeService.SendProgressUpdate(msg.UserID, msg, &Progress{
        Current: 0,
        Total:   scope.GetMessageCount(),
        Message: "Начинаем обработку...",
    })
    
    return msg, nil
}

// executeCommandAsync выполняет команду в фоне с обновлением прогресса
func (s *InteractiveCommandService) executeCommandAsync(
    ctx context.Context,
    msg *InteractiveMessage,
    scope *MessageScope,
) {
    // 1. Получить сообщения для обработки
    messages, err := s.chatRepo.GetMessagesByScope(ctx, scope)
    if err != nil {
        s.handleError(ctx, msg, err)
        return
    }
    
    // 2. Выполнить команду с прогрессом
    progressChan := make(chan Progress, 10)
    resultChan := make(chan interface{}, 1)
    errorChan := make(chan error, 1)
    
    go s.aiService.ExecuteCommand(
        ctx,
        msg.CommandType,
        messages,
        progressChan,
        resultChan,
        errorChan,
    )
    
    // 3. Отправлять обновления прогресса
    for {
        select {
        case progress := <-progressChan:
            s.realtimeService.SendProgressUpdate(msg.UserID, msg, &progress)
        
        case result := <-resultChan:
            msg.State = InteractiveStateCompleted
            msg.Result = result
            msg.Status = "completed"
            s.chatRepo.UpdateInteractiveMessage(ctx, msg)
            s.realtimeService.SendCompletedMessage(msg.UserID, msg, result)
            return
        
        case err := <-errorChan:
            s.handleError(ctx, msg, err)
            return
        }
    }
}

// resolveScope разрешает область применения на основе выбора
func (s *InteractiveCommandService) resolveScope(
    ctx context.Context,
    msg *InteractiveMessage,
    optionId string,
) (*MessageScope, *ScopePreview, error) {
    var scope *MessageScope
    
    // Найти опцию
    var option MessageOption
    for _, opt := range msg.Options {
        if opt.ID == optionId {
            option = opt
            break
        }
    }
    
    switch option.Scope {
    case "last_message":
        // Получить последнее сообщение пользователя в проекте
        lastMsg, err := s.chatRepo.GetLastUserMessage(ctx, msg.UserID, msg.ProjectID)
        if err != nil {
            return nil, nil, err
        }
        scope = &MessageScope{
            Type:      "last_message",
            MessageIDs: []string{lastMsg.ID},
        }
        
    case "current_thread":
        // Получить текущую ветку обсуждения
        thread, err := s.chatRepo.GetCurrentThread(ctx, msg.UserID, msg.ProjectID)
        if err != nil {
            return nil, nil, err
        }
        messageIDs := make([]string, len(thread.Messages))
        for i, m := range thread.Messages {
            messageIDs[i] = m.ID
        }
        scope = &MessageScope{
            Type:      "current_thread",
            MessageIDs: messageIDs,
        }
        
    case "entire_chat":
        // Получить все сообщения чата (с лимитом)
        limit := 100 // можно настраивать
        messages, err := s.chatRepo.GetRecentMessages(ctx, msg.ProjectID, limit)
        if err != nil {
            return nil, nil, err
        }
        messageIDs := make([]string, len(messages))
        for i, m := range messages {
            messageIDs[i] = m.ID
        }
        scope = &MessageScope{
            Type:      "entire_chat",
            MessageIDs: messageIDs,
            MaxMessages: &limit,
        }
        
    case "custom_range":
        // Предоставить интерфейс для выбора диапазона
        // Это будет обработано на frontend
        scope = &MessageScope{
            Type: "custom_range",
        }
    }
    
    // Создать предпросмотр
    preview := &ScopePreview{
        MessageCount: len(scope.MessageIDs),
        WordCount:    s.estimateWordCount(scope.MessageIDs),
        TimeSpan:     s.calculateTimeSpan(scope),
    }
    
    return scope, preview, nil
}

    // Обрабатывает команду и создаёт интерактивное сообщение

// Типы WebSocket сообщений для интерактивных сообщений
type WSMessage struct {
    Type    string      `json:"type"`
    Payload interface{} `json:"payload"`
}

// Типы сообщений:
const (
    WSInteractiveMessage = "interactive_message"
    WSConfirmationPreview = "confirmation_preview"
    WSProgressUpdate      = "progress_update"
    WSCompletedMessage    = "completed_message"
    WSErrorMessage        = "error_message"
)

// Отправка через WebSocket
func (s *RealtimeService) SendInteractiveMessage(userID string, msg *InteractiveMessage) {
    s.SendToUser(userID, WSMessage{
        Type:    WSInteractiveMessage,
        Payload: msg,
    })
}

func (s *RealtimeService) SendConfirmationPreview(userID string, msg *InteractiveMessage, preview *ConfirmationPreview) {
    s.SendToUser(userID, WSMessage{
        Type: WSConfirmationPreview,
        Payload: map[string]interface{}{
            "messageId": msg.ID,
            "preview":   preview,
        },
    })
}

    s.SendToUser(userID, WSMessage{
        Type: WSProgressUpdate,
        Payload: map[string]interface{}{
            "messageId": msg.ID,
            "progress":  progress,
        },
    })
}

## Критерии приемки

### Функциональные требования
- [ ] Поддерживаются интерактивные сообщения для основных команд (recognize, extract, analyze, etc.)
- [ ] Пользователи могут выбрать область применения команды (последнее сообщение, ветка, весь чат, диапазон)
- [ ] Перед выполнением показывается предпросмотр и статистика
- [ ] Отображается прогресс выполнения для долгих операций
- [ ] Результаты отображаются в удобном формате
- [ ] Поддерживается отмена выполнения команды

### Пользовательский опыт
- [ ] Кнопки выбора интуитивно понятны и информативны
- [ ] Предпросмотр показывает точную информацию о том, что будет обработано
- [ ] Прогресс выполнения предоставляет достаточно информации
- [ ] Интерфейс отзывчивый и без задержек

### Производительность
- [ ] Команды выполняются без блокировки основного интерфейса
- [ ] WebSocket соединение стабильно поддерживает обновления в реальном времени
- [ ] Обработка больших объёмов сообщений эффективна

### Совместимость
- [ ] Система интегрирована с существующей системой команд
- [ ] Работает с системой распознавания артефактов (CR-003)
- [ ] Совместимо со всеми типами AI-моделей

## Приоритет

**Высокий** - критично для гибкости использования команд в чате

## Оценка времени

**50-70 часов** - комплексная система интерактивности:
- Backend модели и состояния: 8-12 часов
- Сервис обработки интерактивных команд: 16-20 часов
- Определение и разрешение областей: 12-16 часов
- WebSocket интеграция: 8-12 часов
- Frontend компоненты: 16-20 часов
- UI для выбора областей и диапазонов: 10-14 часов
- Тестирование и отладка: 8-12 часов

## Связанные задачи

- Интеграция с системой распознавания артефактов (CR-003)
- Расширение набора поддерживаемых команд
- Оптимизация производительности для больших объёмов данных
- Кэширование результатов часто используемых команд
- Поддержка сохранения пользовательских настроек областей
- Экспорт и импорт шаблонов команд

## Статус

**Планируется** - ожидает реализации

## Дополнительные соображения

### Расширяемость команд

Система должна быть легко расширяемой для новых команд:

```go
// Регистрация новых команд
type CommandHandler interface {
    CanHandle(commandType string) bool
    GetScopeOptions() []MessageOption
    Execute(ctx context.Context, messages []ChatMessage, progress chan Progress) (interface{}, error)
}

// Регистрация хендлеров
commandRegistry.Register(&RecognizeEntitiesHandler{})
commandRegistry.Register(&ExtractMetricsHandler{})
commandRegistry.Register(&AnalyzeSentimentHandler{})
```

### Пользовательские области

В будущем можно добавить:
- Сохранённые области (named scopes)
- Умные области (AI-определённые релевантные контексты)
- Поиск по содержимому в выбранной области

### История выполнения

- Логирование всех выполненных команд
- Возможность повторного выполнения с теми же параметрами
- Отображение истории выполнения команд
