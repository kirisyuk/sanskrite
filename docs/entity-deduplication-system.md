# Entity Deduplication System

## Overview

Система дедупликации сущностей для онтологий, которая позволяет находить и объединять дубликаты сущностей с учетом различных вариантов написания, транслитераций и алиасов.

## Проблема

В онтологиях могут появляться дубликаты сущностей из-за:
- Разных транслитераций (например, "Китай" vs "Кытай")
- Разных систем транслитерации (кириллица vs латиница)
- Разных форматов названий (например, "Apple Inc." vs "Apple")
- Разных языков (например, "Япония" vs "Japan")

## Решение

Система использует многоуровневый подход к дедупликации:

### 1. EntityResolver

`EntityResolver` использует несколько стратегий для поиска существующих сущностей:

1. **Точное совпадение canonicalName** - быстрая проверка по нормализованному имени
2. **Поиск по aliases** - проверка всех алиасов сущности
3. **LLM-проверка** - использование Gemini для определения одинаковых сущностей
4. **Семантическое сходство** - использование embeddings для поиска похожих сущностей
5. **Транслитерация** - нормализация кириллицы в латиницу

### 2. Нормализация имен

`normalizeName` выполняет следующие шаги:
- Приведение к lowercase
- Удаление лишних пробелов
- Удаление диакритиков
- Нормализация общих вариаций написания (`normalizeCommonVariations`)

### 3. Нормализация вариаций

`normalizeCommonVariations` содержит маппинг известных вариаций:
- "Китай" / "Кытай" / "China" → "китай"
- "Япония" / "Japan" → "япония"
- "США" / "USA" / "United States" → "соединенные штаты америки"

### 4. LLM-проверка

LLM используется для определения одинаковых сущностей с учетом:
- Разных транслитераций
- Разных языков
- Разных форматов названий
- Wikidata ID (если сущности имеют одинаковый Wikidata ID, они точно одинаковые)

## Capabilities

### entity_search

Поиск сущностей с автоматической дедупликацией.

**Input:**
```json
{
  "query": "Китай" | ["Китай", "Кытай"],
  "entityType": "Location" (optional),
  "maxResults": 10 (optional)
}
```

**Output:**
```json
{
  "entities": [
    {
      "id": "entity_id",
      "canonicalName": "Китай",
      "type": "Location",
      "aliases": ["China", "Кытай"],
      "wikidataId": "Q148",
      "matchedQuery": "Китай"
    }
  ],
  "count": 1
}
```

### entity_deduplicate

Дедупликация существующих сущностей.

**Input:**
```json
{
  "entityIds": ["entity_id_1", "entity_id_2", "entity_id_3"]
}
```

**Output:**
```json
{
  "duplicates": [
    ["entity_id_1", "entity_id_2"]
  ],
  "merged": [
    {
      "mainEntityId": "entity_id_1",
      "mainEntityName": "Китай",
      "mergedEntityIds": ["entity_id_2"]
    }
  ]
}
```

**Процесс:**
1. Загружает все указанные сущности
2. Использует LLM для определения групп дубликатов
3. Выбирает главную сущность (предпочтительно с Wikidata)
4. Объединяет алиасы и данные
5. Помечает остальные как deprecated

### entity_relation_build

Построение графа связей между сущностями.

**Input:**
```json
{
  "entityId": "entity_id",
  "maxDepth": 3
}
```

**Output:**
```json
{
  "entityId": "entity_id",
  "relations": [
    {
      "relationId": "relation_id",
      "subjectId": "entity_id",
      "predicate": "locatedIn",
      "objectId": "parent_entity_id",
      "direction": "subjectToObject",
      "depth": 1
    }
  ],
  "count": 10
}
```

**Процесс:**
1. Начинает с указанной сущности
2. Рекурсивно строит граф связей до указанной глубины
3. Избегает циклов через `visited` map

## Использование в Agent Jobs

Пример job для дедупликации сущностей:

```json
{
  "agentId": "entity_deduplication",
  "task": {
    "entityIds": ["entity_id_1", "entity_id_2"]
  },
  "steps": [
    {
      "id": "deduplicate",
      "capability": "entity_deduplicate",
      "input": {
        "entityIds": ["entity_id_1", "entity_id_2"]
      },
      "isCritical": false
    },
    {
      "id": "build_relations",
      "capability": "entity_relation_build",
      "input": {
        "entityId": "{{deduplicate.output.merged[0].mainEntityId}}",
        "maxDepth": 3
      },
      "dependsOn": ["deduplicate"],
      "isCritical": false
    }
  ]
}
```

## Интеграция с Wikidata

Система использует Wikidata для:
- Определения одинаковых сущностей (если у двух сущностей одинаковый Wikidata ID, они точно одинаковые)
- Обогащения сущностей дополнительными данными
- Получения алиасов и переводов названий

## Ограничения

1. **Производительность**: LLM-проверка может быть медленной для больших наборов сущностей
2. **Точность**: LLM может ошибаться в определении дубликатов
3. **Глубина связей**: Ограничена максимальной глубиной (по умолчанию 5 уровней)

## Будущие улучшения

1. Кэширование embeddings для сущностей
2. Использование векторного поиска для быстрого поиска похожих сущностей
3. Автоматическое обогащение вариаций написания из Wikidata
4. Поддержка других баз знаний (DBpedia, GeoNames и т.д.)
