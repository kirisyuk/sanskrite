# Типовой UX-сценарий работы с Horizon

## Обзор

Данный документ описывает типовой пользовательский сценарий работы с системой Horizon, включая вход, процесс сборки графа и профессиональный интерфейс Cockpit. Этот сценарий определяет структуру UI и влияет на визуальный дизайн системы.

## Структура путей

### Фронтенд
Все компоненты Horizon размещаются под путем `/horizon`:
- `/horizon` — главная страница (The Hook)
- `/horizon/assemble/:lensId` — экран сборки графа (The Sled)
- `/horizon/cockpit/:lensId` — профессиональный интерфейс (The Cockpit)
- `/horizon/lenses` — список всех Lens проекта

### Бэкенд
Все API endpoints размещаются под путем `/api/horizon`:
- `/api/horizon/lenses` — управление Lens
- `/api/horizon/fragments` — работа с HorizonFragment
- `/api/horizon/scout` — Scout Engine endpoints
- `/api/horizon/propagation` — Propagation Engine endpoints
- `/api/horizon/watchdog` — Watchdog endpoints

## Этап 1: The Hook (Крючок первого входа)

### Метафора
Не «Поле чата», а **«Командная строка реальности»**.

### Описание интерфейса

**Центральный элемент**: Массивный, фокусный input в центре экрана

**Плейсхолдер**: `"Define your Lens target..."` (Определите цель Линзы)

**Ключевая особенность**: Live Entity Recognition

Как только пользователь начинает печатать (например, `"Risks for Tesla..."`), система **не ждет Enter**. Она начинает работать мгновенно:

1. **Выпадающий список предлагает Сущности** (не продолжение фразы):
   ```
   Tesla Inc. (Organization) [US/Auto]
   Tesla Gigafactory Berlin (Facility) [DE/Mfg]
   Tesla Model 3 (Product) [US/Auto]
   ```

2. **Рядом появляются «чипсы» (фильтры)**:
   - `Horizon: Tier-2` (по умолчанию)
   - `Focus: Supply Chain`
   - `Depth: 3 levels`

3. **Кнопка действия**: 
   - Не `"Send"` (Отправить)
   - А `"Assemble Lens"` (Собрать Линзу) или `"Initialize"`
   - Это создает ощущение запуска сложного процесса, а не начала болтовни

### API Endpoints

**POST** `/api/horizon/entities/search`
- Поиск сущностей по тексту (Live Entity Recognition)
- Возвращает список релевантных сущностей с их типами и путями

**POST** `/api/horizon/lenses`
- Фактический assemble: создание нового Lens (scope задаётся canonical paths выбранных сущностей)
- Запускает процесс сборки/освежения: создаются Scout jobs для scope

### Пример запроса

```json
POST /api/horizon/lenses
{
  "projectId": "uuid",
  "name": "Tesla Supply Chain Risks",
  "scope": [
    "/org/tesla"
  ],
  "viewConfig": {
    "depth": 3,
    "horizon": "Tier-2",
    "focus": "Supply Chain"
  }
}
```

## Этап 2: The "Sled" (Процесс сборки графа)

### Метафора
После нажатия `"Assemble"` мы **не показываем спиннер** «Думаю...». Мы показываем **процесс сборки мира**. Это оправдывает ожидание и ценность.

### Описание интерфейса

**Экран «Сборки» (The Assembly View)**: Пользователь видит, как из пустоты проявляется граф.

#### Phase 1: Decomposition
В центре появляется логотип Tesla. От него отстреливают лучи:
- `"Batteries"`
- `"Chips"`
- `"Logistics"`
- `"Energy"`

#### Phase 2: Cache Hit
Часть узлов мгновенно становится твердой и цветной (это HorizonFragment, которые мы взяли из кэша). 

**Подпись**: `«Restored from System Memory»`

**Визуально**: Узлы имеют зеленый цвет, анимация появления плавная.

#### Phase 3: Scouting
Другие ветки полупрозрачные, пульсируют. Рядом бегут логи:

```
> Scout-1 deployed to Reuters API...
> Scout-2 analyzing Lithium prices in Chile...
> Entity Resolved: "CATL" == "Contemporary Amperex Tech"...
> Frame extracted: operational_health = 0.85 (confidence: 0.92)
> Critic verified: Evidence sufficient
```

**Визуально**: 
- Полупрозрачные узлы с пульсацией
- Лог-панель справа с прокруткой
- Прогресс-бар: `Scouting: 3/7 sources completed`

#### Phase 4: Ready
Граф стабилизируется. Появляется кнопка `"Enter Cockpit"`.

**Психология**: Мы показали работу. Пользователь понимает, почему это стоило денег/времени.

### API Endpoints

**GET** `/api/horizon/lenses/:lensId/assembly-status`
- Возвращает текущий статус сборки графа
- WebSocket: общий `/ws` + подписка на `projectId` для real-time обновлений (`horizon.assembly.*`, `horizon.scout.job.*`, `horizon.graph.*`)

**GET** `/api/horizon/lenses/:lensId/graph`
- Возвращает текущее состояние графа (для визуализации)

### Пример ответа

```json
GET /api/horizon/lenses/:lensId/assembly-status
{
  "status": "scouting",
  "phase": "scouting",
  "progress": 0.43,
  "phases": {
    "decomposition": { "status": "completed", "nodes": 5 },
    "cacheHit": { "status": "completed", "nodes": 12 },
    "scouting": { 
      "status": "in_progress", 
      "completed": 3,
      "total": 7,
      "logs": [
        "Scout-1 deployed to Reuters API...",
        "Scout-2 analyzing Lithium prices in Chile..."
      ]
    },
    "ready": { "status": "pending" }
  },
  "graph": {
    "nodes": [...],
    "edges": [...]
  }
}
```

## Этап 3: The Cockpit UI (Профессиональный интерфейс)

### Метафора
Это основной рабочий экран. Он **не похож на чат**. Он похож на **IDE (как VS Code)** или **терминал Bloomberg**.

### Компоновка экрана (Layout)

#### А. Центральная зона: The Canvas (Холст)

**Назначение**: Визуализация графа зависимостей

**Концепция "Река Влияния" (Impact River)**:
- **Слева** — Источники (Сырье, Геополитика)
- **Справа** — Цель Линзы (Tesla)
- **Потоки (трубы)** соединяют их
- Цветовая кодировка: Красный = высокий риск, Зеленый = низкий риск

**Интерактивность**:
- Можно зумить (zoom in/out)
- Можно двигать узлы (drag & drop)
- Клик на узел открывает Inspector (правая панель)
- Двойной клик — Deep Dive (детальный анализ)

**Туман (Fog)**:
- Периферия размыта
- Там кнопки `+ Deep Dive` для расширения графа

#### Б. Правая панель: The Inspector (Инспектор)

**Контекстная панель**, меняется от того, что выбрано на Холсте.

**Если ничего не выбрано**:
- Сводка Линзы:
  - `Total Risk Score: 0.72` (High)
  - `Top 3 Threats`:
    1. Lithium supply disruption (0.85)
    2. Port congestion in Hamburg (0.68)
    3. Chip shortage escalation (0.61)

**Если выбран Узел** (например, Порт):
- **Карточка Фактора**:
  - График `currentValue` (пропускная способность)
  - Метрики: `operational_health: 0.65`, `capacity_utilization: 0.92`
  - Тренд: `↓ Decreasing`
  
- **Evidence**:
  - Список новостей/отчетов, на основе которых Скаут сделал вывод
  - Каждый элемент содержит:
    - Заголовок источника
    - Цитату (quote)
    - Confidence score
    - Ссылку «Оспорить» (для запуска Критика)
  
- **Metadata**:
  - Когда обновлено: `Last updated: 2 hours ago`
  - Сколько стоит мониторинг: `Watchdog cost: $0.15/day`
  - Источники данных: `3 sources active`

#### В. Левая панель: Navigation & Feeds

**Список Линз**:
- Быстрое переключение между проектами:
  - `Tesla` (активна)
  - `iPhone Supply Chain`
  - `Macro-2025`

**Live Feed**:
- Лента событий только по текущей Линзе:
  ```
  [10 min ago] Watchdog Alert: Strike at Port of Hamburg (Criticality: High)
  [2 hours ago] Fragment Updated: /infra/port/hamburg (operational_health: 0.65 → 0.58)
  [5 hours ago] Scout Completed: /org/catl (confidence: 0.92)
  ```

#### Г. Нижняя панель: Simulation Bar (Симулятор)

**Метафора**: «Пульт управления реальностью»

**Элементы**:
- **Таймлайн**: `Now` — `+30 Days` — `+6 Months`
- **Кнопка "What-If Mode"**: 
  - При нажатии интерфейс меняет акцентный цвет (например, на фиолетовый)
  - Появляются слайдеры на узлах
  - Можно «убить» узел и смотреть, как красная волна идет по Реке

**Пример сценария**:
1. Пользователь включает What-If Mode
2. Выбирает узел "Port of Hamburg"
3. Устанавливает `operational_health = 0.0` (полная остановка)
4. Система показывает распространение влияния:
   - Красная волна идет по графу
   - Обновляются метрики зависимых узлов
   - Показывается итоговый риск для Tesla: `0.72 → 0.89`

### API Endpoints

**GET** `/api/horizon/lenses/:lensId/cockpit`
- Возвращает полное состояние Cockpit (граф, метрики, события)

**GET** `/api/horizon/lenses/:lensId/fragments/:fragmentId`
- Детальная информация о выбранном HorizonFragment (для Inspector)

**POST** `/api/horizon/lenses/:lensId/simulate`
- Запуск What-If симуляции
- Принимает изменения метрик и возвращает прогноз распространения влияния

**GET** `/api/horizon/lenses/:lensId/events`
- Лента событий для Live Feed

**WebSocket**: общий `/ws` + подписка на `projectId`
- Real-time обновления графа, метрик, событий (`horizon.*`)

Подробности реализации: [Realtime (implementation)](../realtime.md).

## Этап 4: Co-Pilot (Чат как вспомогательный инструмент)

### Метафора
Чат **не исчезает**, но он уходит из центра. Он становится **Co-Pilot** (кнопка в углу или выезжающая панель).

### Сценарии использования Чата в Про-интерфейсе

#### 1. Объяснение
**Запрос**: `"Почему этот узел красный?"`

**Действие**: Чат читает Evidence и объясняет:
```
Узел "Port of Hamburg" имеет operational_health = 0.58 (низкий) из-за:
1. Забастовка портовых рабочих (Reuters, 2 часа назад)
2. Перегрузка контейнеров (Port Authority Report, 5 часов назад)
3. Задержки в обработке грузов (Bloomberg, 1 день назад)

Confidence: 0.92
```

#### 2. Навигация
**Запрос**: `"Покажи только поставщиков Tier-2 в Китае"`

**Действие**: Чат применяет фильтр к Холсту:
- Скрывает все узлы, кроме Tier-2 поставщиков в Китае
- Обновляет визуализацию графа
- Показывает только релевантные связи

#### 3. Генерация отчета
**Запрос**: `"Сделай PDF-сводку для совета директоров"`

**Действие**: Чат берет данные графа и пишет текст:
- Анализирует текущее состояние всех узлов
- Формирует Executive Summary
- Выделяет ключевые риски
- Генерирует PDF с графиками и метриками

### API Endpoints

**POST** `/api/horizon/co-pilot/chat`
- Отправка сообщения в Co-Pilot
- Возвращает ответ с действиями (объяснение, фильтр, генерация отчета)

**POST** `/api/horizon/co-pilot/explain`
- Объяснение состояния узла или метрики

**POST** `/api/horizon/co-pilot/filter`
- Применение фильтра к графу на основе естественного языка

**POST** `/api/horizon/co-pilot/generate-report`
- Генерация отчета на основе данных графа

## Резюме UX-перехода

### Вход
- Не «Спроси меня», а **«Сфокусируй Линзу»**
- Автокомплит сущностей сразу дает понять, что система знает структуру мира

### Ожидание
- **Визуализация Сборки Графа**
- Шоу работы агентов
- Понятно, почему это стоило денег/времени

### Работа
- **Кокпит**: Управление потоками, инспекция узлов, симуляция сценариев
- Профессиональный интерфейс, похожий на IDE или Bloomberg Terminal

### Чат
- **Вспомогательный инструмент** (объяснялка/писатель), а не основной интерфейс
- Co-Pilot для навигации, объяснений и генерации отчетов

## Влияние на визуальный дизайн

### Цветовая палитра
- **Красный**: Высокий риск, критические узлы
- **Зеленый**: Низкий риск, стабильные узлы
- **Желтый**: Средний риск, предупреждения
- **Фиолетовый**: What-If Mode активен
- **Синий**: Активные элементы, ссылки

### Типографика
- **Моноширинный шрифт**: Для логов, метрик, кода
- **Sans-serif**: Для интерфейса, заголовков
- **Размеры**: Крупные для важных метрик, мелкие для деталей

### Анимации
- **Плавные переходы**: При появлении узлов, изменении метрик
- **Пульсация**: Для узлов в процессе Scouting
- **Волна**: Для распространения влияния в What-If Mode

### Компоненты
- **Canvas**: Интерактивный граф с zoom, pan, drag & drop
- **Inspector**: Контекстная панель с карточками, графиками, списками
- **Live Feed**: Лента событий с прокруткой и фильтрацией
- **Simulation Bar**: Таймлайн и слайдеры для What-If Mode
- **Co-Pilot**: Выдвижная панель чата с поддержкой команд
